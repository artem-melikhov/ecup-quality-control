# E-CUP 2026: Контроль качества

Решение задачи проверки карточек товаров из категорий БАД и легковоспламеняющихся товаров.

Описание задачи: https://ods.ai/competitions/e-cup-2026-quality

## Запуск

```bash
python submit/run.py -i test.csv -o submit.csv
```

Текстовые признаки TF-IDF используются с логистической регрессией.
Для БАД применяется NB-взвешивание, для ЛВ объединяются два текстовых канала.
Обучающие данные находятся в `submit/train_data.csv`.
На выходе CSV со столбцами `id` и `result` в формате соревнования.

## LLM

Для ЛВ добавлены сигналы Gemma и Qwen с примерами из трейна.
Похожие товары отбираются по символьному TF-IDF, без повторения групп почти-дублей.
Коэффициенты объединения лежат в `submit/params.json`.
При отсутствии CUDA используются доступные текстовые сигналы.

## Обработка карточек

HTML удаляется до построения признаков. В комментарии включаются цитаты из карточек.
Примеры для LLM сначала ищутся среди товаров той же подкатегории.

## Фотографии

Модуль `submit/ocr.py` читает фотографии из папок с ID товаров через Tesseract.
Поддерживаются русский и английский языки, EXIF-ориентация и кэш результатов.
На товар обрабатывается до пяти фото.

OCR включён в признаки моделей и промпты LLM. Для трейна можно заранее подготовить
`submit/train_ocr.csv` со столбцами `id` и `ocr_text`.
Локальные пути задаются в `ocr.local.json`, образец настроек находится в
`ocr.local.example.json`. Файл локальных настроек в Git не включается.

В Dockerfile устанавливаются Tesseract, языковые данные и Pillow.
Для сборки образа используется `docker build -t artemmelikhov/ecup-quality-ocr:1.0 .`.

## Визуальные признаки

Модуль `submit/vision.py` извлекает признаки через замороженный CLIP ViT-B/32.
Признаки отдельных фото усредняются и нормализуются в один вектор товара.
Поверх них обучаются отдельные логистические регрессии для двух категорий.
Веса CLIP размещаются локально, загрузки из интернета при обработке нет.
